## SECTION 1: CRITICAL ISSUES (Must Fix Before Real Money Trading)

### C1. PLAINTEXT CREDENTIALS IN settings.json
**Severity**: CRITICAL
**File**: `settings.json` lines 8-9
**Issue**: `password: "Bharat@123"` and `totp_secret: "I25KMXCXICZ3QIFXR5RXTSY3BGUYP6YR"` stored in plaintext.

**Root Cause**: `settings_gui.py:1173-1221` — `save_settings()` builds a raw dict and calls `current_settings.update(new_settings)` then `settings_mgr.save()`. This bypasses `SettingsManager.set()` which is where encryption via `_is_sensitive_field()` happens. The encryption system EXISTS but is NEVER CALLED during save.

**Fix Plan**:
```python
# In settings_gui.py save_settings(), replace bulk update with per-field set():
sensitive_fields = [
    ("broker.api_key", self.api_key_entry.get()),
    ("broker.api_secret", self.api_secret_entry.get()),
    ("broker.password", self.password_entry.get()),
    ("broker.access_token", self.access_token_entry.get()),
    ("broker.totp_secret", self.totp_entry.get()),
    ("notifications.telegram_bot_token", self.tg_token_entry.get()),
]
for key_path, value in sensitive_fields:
    self.settings_mgr.set(key_path, value)  # This triggers encryption

# Non-sensitive fields can still use bulk update
```

**mStock API Impact**: NONE. The API receives decrypted values at runtime. Encryption is at-rest only.
**Zerodha Impact**: N/A (not used).

### C2. CREDENTIALS IN GIT HISTORY
**Severity**: CRITICAL
**File**: `settings.json` is tracked by git (shown in `git status`)

**Fix Plan**:
1. `git rm --cached settings.json`
2. Add `settings.json` to `.gitignore`
3. Create `settings_default.json` (template with empty values) for git
4. ROTATE ALL CREDENTIALS: API key, API secret, password, TOTP secret via mStock portal
5. Add `.encryption_key` to `.gitignore` as well

**mStock API Impact**: Must regenerate API key/secret from mStock Developer Console. TOTP secret must be re-enrolled. Access token auto-regenerates via TOTP.

### C3. OPERATOR PRECEDENCE BUG — SILENT ERROR SWALLOWING
**Severity**: HIGH
**File**: `kickstart.py:1325`
```python
# CURRENT (BUGGY):
if "TokenException" or "invalid session" in error_str:
# ALWAYS TRUE because "TokenException" is truthy

# CORRECT:
if "TokenException" in error_str or "invalid session" in error_str:
```
**Impact**: Every exception in `safe_get_positions()` is treated as a token issue, hiding real bugs (network errors, data corruption, etc.)

**mStock API Impact**: Could mask real API errors (e.g., rate limiting, schema changes).

### C4. DUPLICATE SettingsManager INSTANCES (4 copies)
**Severity**: HIGH
**File**: `kickstart.py` lines 68, 368, 1168 + `settings_gui.py` line 29

**Issue**: Four independent `SettingsManager()` instances read `settings.json` at different times. If one saves while another has stale data, settings can regress.

**Fix Plan**: Implement singleton pattern:
```python
# settings_manager.py
class SettingsManager:
    _instance = None

    @classmethod
    def get_instance(cls, settings_file="settings.json"):
        if cls._instance is None:
            cls._instance = cls(settings_file)
        return cls._instance
```
Then replace all `SettingsManager()` calls with `SettingsManager.get_instance()`.

**mStock API Impact**: NONE. This is internal state management.

### C5. DOUBLE SAVE IN settings_gui.py
**Severity**: LOW
**File**: `settings_gui.py:1218-1221`
```python
self.settings_mgr.save()
# Save to JSON
self.settings_mgr.save()  # DUPLICATE
```
**Fix**: Delete the duplicate line.

## SECTION 2: SECURITY ISSUES

### SEC1. TOTP CODE LOGGED IN PLAINTEXT
**File**: `kickstart.py:1023`
```python
log_ok(f"Generated TOTP: {otp_code}")
```
**Fix**: Remove or mask: `log_ok(f"Generated TOTP: ***{otp_code[-2:]}")`

### SEC2. API KEY PARTIALLY LOGGED
**File**: `kickstart.py:1268`
```python
log_ok(f"   Token present: {bool(ACCESS_TOKEN)}, API Key: {API_KEY[:10]}...")
```
**Fix**: `log_ok(f"   Token present: {bool(ACCESS_TOKEN)}, API Key: {'***' + API_KEY[-4:] if API_KEY else 'NONE'}")`

### SEC3. ENCRYPTION KEY IN PROJECT ROOT
**File**: `.encryption_key` (auto-generated by `settings_manager.py:149`)
**Fix**: Add to `.gitignore`. Document that production should use `ARUN_ENCRYPTION_KEY` env var.

### SEC4. DEBUG REQUEST LOGGING
**File**: `kickstart.py:296`
```python
print(f"DEBUG REQ: {method} {url}")
```
This logs every API call URL to console. In production, sensitive query params could leak.
**Fix**: Remove or gate behind `DEBUG` flag.

## SECTION 3: RELIABILITY ISSUES

### R1. NO THREAD SAFETY ON SHARED GLOBALS
**Files**: `kickstart.py` — `CYCLE_QUOTES`, `FETCH_STATE`, `live_positions`, `config_dict`
**Issue**: Mutable dicts shared between GUI thread and background workers with no locks. Spin-wait pattern (line 224) is a race condition.
**Fix Plan**: Add `threading.Lock()` around shared state mutations.
**mStock API Impact**: NONE (internal concurrency issue).

### R2. SCANNER STOP DOESN'T PROPAGATE
**File**: `sensei_v1_dashboard.py:stop_scanner()` sets `self.scanner_running = False` but never calls `scanner.stop()` on the `MACDScanner` instance.
**Fix**: Store scanner instance as `self.active_scanner` and call `self.active_scanner.stop()`.

### R3. UNREACHABLE CODE
**File**: `state_manager.py:44-46`
```python
return merged          # Returns here
logging.info(...)      # DEAD CODE
return merged           # DEAD CODE
```
**Fix**: Delete lines 45-46.

### R4. DEAD CODE IN fetch_orders()
**File**: `kickstart.py:703` — duplicate `return []` after function already returned.
**Fix**: Delete the orphan return.

## SECTION 4: mSTOCK API REFERENCE (For Change Validation)

### Authentication
- **Header Format**: `Authorization: token {API_KEY}:{ACCESS_TOKEN}`
- **Required**: `X-Mirae-Version: 1` on all requests
- **TOTP Auto-Login**: `POST /openapi/typea/session/verifytotp` with `{api_key, totp}`
- **Token Refresh**: Auto-triggered on 401/403 via `safe_request()` → `perform_auto_login()`

### Endpoints Used
| Endpoint | Method | Purpose |
|----------|--------|---------|
| `/session/verifytotp` | POST | TOTP auto-login |
| `/session/token` | POST | Manual token generation |
| `/connect/login` | POST | Initial login (needs OTP) |
| `/instruments/quote/ohlc?i=EX:SYM` | GET | Live quotes |
| `/instruments/historical/{EX}/{TOKEN}/{TF}` | GET | Historical candles |
| `/portfolio/holdings` | GET | CNC holdings |
| `/portfolio/positions` | GET | Intraday positions |
| `/orders` | GET | Today's orders |
| `/orders/{variety}` | POST | Place order |
| `/orders/cancel` | POST | Cancel order |
| `/user/fundsummary` | GET | Account balance |
| `/limits/getCashLimits` | GET | Cash limits (connectivity check) |

### Key API Behaviors
- REIT symbols (EMBASSY, BIRET) work on BSE as EQ, NOT on NSE via OHLC API
- Numeric tokens work for `/instruments/historical` but NOT for `/instruments/quote/ohlc`
- Orders API returns array `[{status, message}]` not object
- Holdings response: `{data: [{tradingsymbol, quantity, price, last_price, pnl, used_quantity}]}`

### Zerodha Status
**NOT IMPLEMENTED**. No Kite API references exist in the codebase. The broker dropdown in Settings GUI shows "zerodha" as an option but there is no backend implementation.

## SECTION 5: SCALABILITY & MODERNIZATION

### Current Limitations
1. **Sequential stock scanning**: 1200 stocks at 0.2s each = 4+ minutes
2. **JSON file-based state**: No concurrent access safety, no transactions
3. **Monolithic kickstart.py**: 1600+ lines, ~40 globals (God module)

### Recommended Improvements (Future Sprints)
1. **Parallel scanning** with `concurrent.futures.ThreadPoolExecutor(max_workers=5)`
2. **SQLite for state** (already used for trades — extend to settings/state)
3. **Module extraction**: Split kickstart.py into `broker_api.py`, `order_manager.py`, `position_tracker.py`, `market_data.py`

## SECTION 6: CODE QUALITY NOTES

### Good Patterns Found
- Graceful degradation with `*_AVAILABLE` flags
- Settings backup rotation (keeps last 5)
- Holdings caching for instant startup
- Capital "Safety Box" separation
- State persistence for crash recovery

- 20+ instances of `except: pass` — should log warnings

- Inconsistent naming: `Ignore_RSI` vs `buy_rsi` in same dict
- `_legacy_UNUSED_run_cycle()` — 850 lines of dead code to remove
