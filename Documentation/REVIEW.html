4. Customer experience — the page dad actually reads

The single biggest UX risk is not readability — it's JARGON. The plan is written for B. The page is for B's father. Any term that leaks from the config file onto the screen is a failure: the page must never render per_stock_amount, max_names_cap, trail_giveback_pct, tranche, knob, or diagnostic. Those become, in his world:

trail_giveback_pct"The safety line is 2% below the best price."

4.1 Size & contrast (non-negotiable for 60+)

Base font
No smaller than 18px body, 22px+ for the money numbers (entry / price / P&L). Use rem, never px, so the OS large-text/zoom setting works.
Contrast
Body text ≥ 7:1 (WCAG AAA). Currency and status numbers should be near-black on the panel.
Color is never the only cue
Profit/loss can't be green-vs-red alone. Always add a +/− sign and the words "+ profit" / "− loss".
Dark mode
Manual, default to light. Provide an obvious "A / A−" text-size toggle.
Money format
Indian groups, round to whole ₹ (₹10,000). Market cap in crore (₹500cr).

4.2 Layout — fewer things, bigger things

One stock = one card
A card per stock: big price, big P&L (+/−), a plain one-line status, a clear action if needed. 2–3 cards max per screen.
Top headline line
First thing on the page: one sentence, e.g. "You have 3 stocks. 1 needs your attention."
Navigation
Few tabs, big buttons (≥ 44px tall), named in words: "Today's picks", "My stocks", "How it works". No hover-only tooltips.
Status / warnings
STRANDED, DEAD NAME, "rope inactive" = a coloured banner at the top in plain words, never a table cell.
Kill switch
Huge, red, unambiguous ("STOP the bot"). Not a toggle.

4.3 Reassurance, not alarms

Frame honest caveats as reassurance. Where the strategy says "it can gap through the rope," the page adds one calm line: "This computer follows fixed rules. It never guesses. It can still be caught by a sudden fall — that's the cost of never selling at a loss." Language: English (confirmed by B). Short sentences, active voice, no investment shorthand.

4.4 Empty states & the honesty rail

No candidates today → "No picks today. That's fine — the bot is picky and waits for a good setup. It will check again tomorrow."
Scoreboard → no confident %; show the count and "This is still a small sample. Not enough trades to judge yet." (matches the ≥30-trade honesty rail.)

5. UX acceptance criteria for step 6 (build in, don't retrofit)

  1. No config variable, code key, or investment-jargon term ever renders on the page.
  2. Body text ≥ 18px / 7:1 contrast; all sizes in rem; a visible text-size toggle.
  3. Profit/loss always shown with sign + the words profit/loss, never colour alone.
  4. One stock = one card; ≤ 3 cards per screen; top line states the one thing he must know.
  5. STRANDED / DEAD NAME / "profit too thin" are top-of-page banners in plain words.
  6. Numeric money uses Indian grouping, whole ₹; market cap in crore.
  7. Kill switch is a large red "STOP" button, not a toggle.
  8. Every empty state has a plain, non-alarming explanation.

Language: English (settled). No translation layer, no toggle.
