2. Architecture

brokers/
  interface.py       BrokerInterface Protocol — the contract both brokers satisfy
  factory.py          get_broker("IN"|"US") — routes to the right implementation
  mstock_adapter.py    Wraps kickstart.py's existing functions, unchanged
  ibkr_broker.py        Real ib_insync implementation
  test_factory.py       Self-test: Protocol conformance, no live calls
  check_ibkr_connection.py   Manual read-only check
  lookup_symbol.py       Read-only: exchange/currency lookup for a ticker
  test_live_order.py      Single-symbol order test, CONFIRM-gated
  buy_with_target.py       Batch buy + auto GTC profit-target sells

Deliberately not done: kickstart.py is not wired to get_broker(). The mStock engine still calls its own functions directly — rewiring the live engine's order path is saved for later, done once, not twice.

deploy/
  setup_ibgateway.sh              Installs Xvfb + IB Gateway + IBC on the VPS
  ibgateway-headless.service      systemd unit: Xvfb + IBC-driven Gateway login
  ibc/config.ini.template         IBC login config — copy, fill in, keep off git
  backup_db.sh                    sqlite .backup (not cp), 30-day retention
  tradingbot-backup.service/.timer   Runs backup_db.sh every 6h via systemd

Backup guardrails: uses sqlite3 .backup, not a raw file copy, so a live write mid-backup can't corrupt the output. Retention only deletes files it wrote itself, never the live database. *.db is already git-ignored. Local-disk only — off-box copy of backups/ not done.

3. Connection details

  • TWS API via ib_insync, socket to IB Gateway — not the Client Portal REST API. Project Vayu hit Malaysia-region access restrictions on that path; this VPS is also Malaysia-based, so this wasn't a theoretical choice.
  • Ports: 4001 = Gateway live, 4002 = Gateway paper. Set via IBKR_PORT, read once at import time — must be set in the environment of whichever process connects, or it silently defaults to paper and fails confusingly.
  • clientId: manual scripts use 7, the dashboard uses 9 — kept different on purpose so they don't collide.
  • Read-Only API: a Gateway setting blocking all order placement server-side. Was on for validation, deliberately turned off before any real order.

4. Real bugs found and fixed

  1. Event loop crash calling IBKR from a web request. ib_insync needs an asyncio event loop per thread; FastAPI's worker threads don't have one by default. Fixed in IBKRBroker.connect().
  2. Order silently discarded after a fast disconnect. An order not yet acknowledged downstream can be dropped if the connection closes too soon. Fixed by waiting for a real status update first.
  3. IBKR_PORT not reaching the dashboard's server process. Silently defaulted to paper port, every call failed with "connection refused" even with Gateway running. Fixed locally and in deploy/setup.sh.
  4. ₹ shown on real USD amounts. Dashboard's money formatter was hardcoded for mStock's rupees, reused blindly on the IBKR tab. Fixed with a separate USD formatter.
  5. NaN crashing the Stocks API endpoint (mStock side) — blank CSV cells become pandas NaN, not valid JSON. Nulled before returning.

5. Known gaps

  • OPEN Direct-routing fee on IUIT/EQQQ — real fee found: $4 smart-routed vs $6 direct-routed minimum. Unresolved.
  • OPEN No stop-loss on the three new positions — GTC sells are profit targets only, no downside protection.
  • OPEN Purchase date is best-effort — only covers today's session; older positions show "unknown." Full history needs a Flex Query report, not built.
  • OPEN Average-cost accounting, not per-lot — fine for a glance, not precise enough for tax reporting.
  • OPEN IB Gateway headless-on-VPS is scripted, not yet deployed — deploy/setup_ibgateway.sh + ibgateway-headless.service + ibc/config.ini.template exist; needs a real run on the VPS with real IBKR login filled in, then verify via check_ibkr_connection.py.
  • OPEN RSI / day-change / position-weight not shown yet — RSI specifically needs historical bars pulled and computed ourselves.
